# Round 2 release — 2026-09-08

Dated record of what changed between the Round-1 submission and the Round-2
build, in release order.

## Voice path stabilized (the big one)

- `@humeai/voice-react` 0.2.14 (silently introduced by an npm audit fix)
  rendered the live call path unusable: its provider enters a render-phase
  update loop under React 19 on every live session. Upgraded to the current
  0.3 line and made the station unmount cleanup ref-stable. Live calls now
  connect and stay connected (verified in real Chromium).
- Live interim transcripts: the caller's words stream while they speak
  (ghost line); only finalized turns feed triage.
- Per-utterance prosody chips on every caller line and the caller's top
  measured emotion on the dispatcher's LIVE strip.

## Safety hardening

- Emotion (prosody) can no longer cross severity-band boundaries
  (`severityBandCeiling`, with test). The deterministic grade decides the
  band; emotion may only sharpen priority inside it.
- Session-local audit wording everywhere: the audit trail is a demonstration
  of the design, stored in the operator's browser for the session.

## Console

- Dispatch routes follow actual roads (OSRM driving profile, cased polyline),
  with the straight-line dashed estimate as the instant/offline fallback.
- Full rename to Kwik 112 across product, code identifiers, and repository.

## Machine-legibility and trust (this release)

- `/for-judges` (three one-click paths, real/simulated/synthetic table),
  `/benchmark` (renders the committed results JSON), `/transcript`
  (VideoObject). Expanded SSR landing with sourced problem evidence.
- Upgraded `llms.txt`, sitemap coverage, MIT license, CI workflow gating on
  the full test suite plus `critical recall === 1.0`, `CODEX_LOG.md`.
- OpenAI-compatible provider support documented (`OPENAI_API_KEY`,
  `OPENAI_BASE_URL`); GLM 4.5 Flash remains the configured provider.
